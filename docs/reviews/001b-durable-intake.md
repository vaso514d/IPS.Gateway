## Result

Intake now stores the transaction, original request, and initial history before returning success. A repeated client reference returns the existing transaction across message types, preserving its current outcome and original payload. Concurrent updates use SQL rowversion: one writer commits current state and history together, while the loser receives an explicit Conflict result.

Application owns intake and the transaction-specific storage interface. Infrastructure owns SQL records, mapping, transactions, and generated migrations. Domain and Contracts are unchanged. The Api host still runs without a database and exposes only its foundation endpoints.
