# Specification 019: the gateway's API document, Swagger UI and a typed gateway client

Status: proposed on main (base 19a9bb6); the owner chose to work on main on 2026-10-17. The owner made three choices on 2026-10-17: Swagger UI, the document served behind a configuration switch, and a new typed client package. On 2026-10-17 the owner approved the specification with the recommended D1, D2 and D3 and asked for 019a.

## Why

A bank integrates in two directions.

- **Gateway to bank.** The bank implements `IClientPaymentReceiver`. 017b and 018 cover this direction completely: Contracts, `IPS.MiidleWear.AspNetCore`, `IPS.MiidleWear.Testing`, the sample, and the receiver's OpenAPI document.
- **Bank to gateway.** The bank calls `IGatewayApi`: the sends, the transaction status and proxy management under `/api/v1`. 017 left this direction for "its own specification". It has four gaps:
  - The Api maps `/openapi/v1.json` in Development only.
  - The `Summary`, `Description` and `Tag` text on the `IGatewayApi` `[RestEndpoint]` attributes never reaches that document. The controllers declare only `ProducesResponseType`.
  - No browsable UI or committed document exists.
  - A bank has to hand-write an `HttpClient` for nine operations, with the gateway's JSON conventions and answer rules: 200 is final, 504 means still waiting, 400 is validation, 404 means unknown, and 503 or 502 is a technical failure.

The owner's 017 decision stands: bank systems are .NET only, packages are the primary channel, and OpenAPI is the generated formal description.

## Scope

Three slices, each reviewed and committed separately.

**019a: the generated documents and Swagger UI**
- Each gateway operation's summary, description, tag and message type come from its `IGatewayApi` `[RestEndpoint]` attribute. The prose is not duplicated.
- The document gets a header (`info`, `servers`) and typed request and answer examples.
- `IGatewayApi`'s class summary currently says sends return "202 + status Processing". It is corrected to the implemented 200, or 504 after the wait.
- Swagger UI shows the gateway document.
- `Api:Documentation:Enabled` controls exposure: always on in Development, off by default elsewhere.
- The receiver document is generated by the core system's own application through `AddIpsCoreReceiverOpenApi` in `IPS.MiidleWear.AspNetCore`.
- Both documents are generated from code. JSON files are written on demand and not committed.

**019b: `IPS.MiidleWear.Client`**
- A packable library: `IpsGatewayClient : IGatewayApi` over `HttpClient`, plus `AddIpsGatewayClient`.

**019c: the bank integration guide**
- `docs/bank-integration/README.md`, one page for a bank team covering both directions.

Not in scope:
- Request signing, mTLS, authentication and `securitySchemes`. A later specification covers them; the client leaves room through `IHttpClientBuilder`.
- Package publication to a feed, and client generation for languages other than .NET.
- Any change to gateway behaviour, routes, wire shapes, workflows or persistence.

## 019a design

Revised on 2026-10-17 (owner): the documents are generated from code, following the annotation approach of the Livestock-Product (Maverick) API. The first cut embedded the wire cases and the committed receiver document in the Api and committed `ips-gateway.json`; that is replaced. Owner decisions for the revision:
- the core system's application generates the receiver document;
- examples are typed C# objects linked to operations by attributes;
- no JSON document is committed; files are generated on demand with `Microsoft.Extensions.ApiDescription.Server`.

**Gateway annotations (`src/IPS.Middleware.Api/Documentation`).**
- Every controller action carries `[GatewayOperation(nameof(IGatewayApi.X))]`, naming the interface method it serves.
- `GatewayOperationTransformer` (an `IOpenApiOperationTransformer`) reads it from the action's `MethodInfo` (`ControllerActionDescriptor`). From the method's `[RestEndpoint]` it sets `summary`, `description`, the tag and an `x-ips-message-type` extension.
- `[RequestExample(nameof(GatewayExamples.X))]` and `[ResponseExample(200, nameof(GatewayExamples.Y))]` name typed DTO instances in `GatewayExamples`. `ExampleOperationTransformer` serializes them with `IpsJson.SerializerOptions`. Only final 200 answers have an example: a 504 carries a status still in progress.
- `GatewayDocumentTransformer` (an `IOpenApiDocumentTransformer`) sets `info` and `servers`, and keeps only the tags operations use.
- Health endpoints carry no attribute and are left as they are.
- Schema property descriptions come from the Contracts XML documentation, which `Microsoft.AspNetCore.OpenApi` 10 reads.

**Header.**
- `info.title` is "IPS gateway API" and `info.version` is the Contracts package version.
- `info.description` gives the shared rules once:
  - `clientReference` makes a send idempotent;
  - 200 is final;
  - 504 returns the current status, and the final one follows by callback or GET;
  - 400 is validation;
  - 503 means the gateway cannot accept the work now.
  - It also points to `AddIpsCoreReceiverOpenApi` for the receiver document.
- `servers` is `https://{gatewayHost}`, with the example default `gateway.bank.example`.
- OpenAPI 3.0, as in 017.

**Exposure.**
- `Api:Documentation:Enabled` is true in Development regardless of its value, and defaults to false elsewhere.
- When enabled, the Api maps:
  - `/openapi/v1.json`;
  - `/swagger`, using `Swashbuckle.AspNetCore.SwaggerUI` only.
- When disabled, both answer 404.
- `StartupSummary` logs the setting, and `docs/configuration.md` documents it.

**The receiver document (`IPS.MiidleWear.AspNetCore`).**
- `AddIpsCoreReceiverOpenApi()` registers the OpenAPI 3.0 document `ips-core-receiver`, and `MapOpenApi()` serves it at `/openapi/ips-core-receiver.json`.
- `MapIpsCoreReceiver` puts its endpoints in that document's group, so the application's own documents do not list them.
- The endpoint metadata already carries the route, summary, description and tag from the contract. `CoreReceiverOpenApi` adds:
  - the header;
  - the `Idempotency-Key` header per delivery;
  - typed examples from `ReceiverExamples`.
- The package gains a `Microsoft.AspNetCore.OpenApi` reference. This changes the 017b dependency rule.
- The sample receiver shows the registration. `tools/IPS.MiidleWear.OpenApi` and `docs/openapi/` are removed.

**On-demand files.** Both projects set `OpenApiGenerateDocuments` with `OpenApiGenerateDocumentsOnBuild=false` and write OpenAPI 3.0 to `artifacts/openapi/`, which is gitignored:

```powershell
dotnet build src/IPS.Middleware.Api -p:OpenApiGenerateDocumentsOnBuild=true
dotnet build samples/IPS.MiidleWear.CoreReceiver.Sample -p:OpenApiGenerateDocumentsOnBuild=true
```

`dotnet-getdocument` runs the Api's `Program`. While it does (Microsoft's documented `GetDocument.Insider` entry-assembly check), the Api:
- skips validation, the startup summary and migration;
- keeps the outgoing and proxy controllers;

so the file describes every operation without configuration or a database.

**Contracts.** The `IGatewayApi` summary correction is XML documentation only, which `public-api.json` does not contain.

## 019b design

**Project.**
- `src/IPS.MiidleWear.Client`, `net10.0`, packable, with the same version as Contracts.
- It references `IPS.MiidleWear.Contracts` and `Microsoft.Extensions.Http` only.
- The gateway does not reference it.

**Registration.**
```csharp
builder.Services.AddIpsGatewayClient(options => options.BaseAddress = new Uri("https://gateway.example"));
// returns IHttpClientBuilder: the bank adds its certificate handler, authentication and resilience
```

**Calls.**
- Each method takes its HTTP method and route from its own `[RestEndpoint]` attribute, so no route is written twice.
- Bodies and answers use `IpsJson.SerializerOptions`.
- The status query sends `messageKind` and `clientReference` in the query string, as the Api binds them.
- The client has no retry policy of its own. Sends are idempotent by `clientReference`, so a bank may retry with its own policy.

**Answers.**
- 200: the `TransactionStatusDto` or `ProxyOperationResultDto`.
- 504 to a send: the `TransactionStatusDto` in the body, which carries a non-final status. This is a normal outcome, not an exception.
- 400: `IpsGatewayValidationException`, with the field errors of the `HttpValidationProblemDetails`.
- 404 to the status query: see D1.
- Anything else, including 502 and 504 from proxy calls, 503, or an unreadable body: `IpsGatewayException`, with the status code and the problem details when present.

**Readme.** `PackageReadmeFile` covers registration, the answer table, and adding a certificate handler.

The empty `docs/bank-integration/examples/` folder is removed.

## Resolved decisions (owner, 2026-10-17)

- **D1. 404 to the status query: the client throws `IpsGatewayNotFoundException`.** Contracts is unchanged; `IGatewayApi.GetTransactionStatusAsync` keeps its non-nullable `TransactionStatusDto`. The alternative was a nullable return, which is a Contracts signature change.
- **D2. Package version: `2.0.0-preview.2`** for Contracts, Client, and the packages that ship with them (`IPS.MiidleWear.AspNetCore` and `IPS.MiidleWear.Testing`). The alternative was to stay at `2.0.0-preview.1`.
- **D3. Swagger UI "Try it out": in Development only.** Elsewhere the UI is read-only, so a shared environment does not invite live sends from a browser.

## Acceptance

**019a**
- Every gateway operation in the served document has the summary, description and tag of its `IGatewayApi` attribute, with exactly one operation per interface method.
- Every controller action names a distinct `IGatewayApi` method whose HTTP method and route it serves.
- Both documents read without errors with `Microsoft.OpenApi` as OpenAPI 3.0.
- Every example deserializes into its DTO with unknown members rejected, and only 200 answers have one.
- The receiver document has exactly the nine operations, the `Idempotency-Key` header on the eight deliveries, and is absent from the application's own document.
- Development serves `/openapi/v1.json` and `/swagger`, and its UI can send. Production with the switch unset answers 404 for both. With the switch true it serves them, and the UI is read-only.
- Both on-demand commands write their file without configuration.

**019b**
- The real client against the in-process Api:
  - each send kind returns 200;
  - a repeated `clientReference` returns the existing status;
  - a send that outlasts the wait returns the 504 status without throwing;
  - an invalid request throws `IpsGatewayValidationException` with the field errors;
  - the status query returns the status, and handles an unknown reference per D1;
  - proxy register, update and remove return the result against the Proxy simulator;
  - 503 throws `IpsGatewayException`.
- The architecture test admits `IPS.MiidleWear.Client` with Contracts and `Microsoft.Extensions.Http` only.
- The package packs with its readme.

**019c**
- The guide's code compiles: it is taken from the sample and the tests.
- Every link resolves.

**Verification.** Release build, the full suite (`-m:1`), format, the EF check (no model change), `git diff --check`, and independent Standards and Spec reviews.

## Implementation notes (019a, 2026-10-17)

- **Revision.** The first cut (one route-matching document transformer, embedded wire cases and receiver document, a committed `ips-gateway.json` with an update switch) passed the full suite (530 unit, 1216 integration). It was replaced at the owner's request by the generated design above.
- **Generation mode.** Without the `GetDocument.Insider` check, `dotnet-getdocument` fails in `ValidateMiddleware`, because enabled execution requires transport settings. The build-time generator also writes OpenAPI 3.1 unless it is given `--openapi-version OpenApi3_0` (`OpenApiGenerateDocumentsOptions`).
- **Examples.** The values follow the Contracts wire cases. The gateway and the receiver package each hold their own copies, because the Api cannot reference the receiver package and Contracts carries no example data. The pacs.008, pacs.009, pacs.004 and status examples therefore exist twice.
- **Interceptors.** The integration tests call `AddOpenApi` themselves. The OpenAPI XML-comment generator intercepts that call, so the test project enables `Microsoft.AspNetCore.OpenApi.Generated` in `InterceptorsNamespaces`.
- **Tests with SQL.** The gateway document needs outgoing execution enabled to list the sends, so its tests use `OutgoingHostFixture` (a SQL test database).
- **Versions.** The four packages are `2.0.0-preview.2` (D2).
- **Swashbuckle.** `Swashbuckle.AspNetCore.SwaggerUI` 10.2.3 depends only on the ASP.NET Core framework. "Try it out" is turned off with an empty `SupportedSubmitMethods`.
- **Found on main.** Commit 7593beb had renamed the Api's `InternalsVisibleTo` to `IPS.Middleware.Integration`, which broke the integration test build (`ICertificateInventory` inaccessible). It is restored to `IPS.Middleware.IntegrationTests`.

## Risks

- **The action link.** A new action without `[GatewayOperation]`, or one naming the wrong method, would lose its description. The annotation test catches both.
- **No committed document.** A change to the documents no longer shows as a JSON diff in review. The tests pin the structure, and the files can be generated and compared by hand.
- **The UI in shared environments.** Enabling the switch exposes the operation list and examples; D3 limits live calls. Authentication is a later specification.
- **The client is unproven with a real bank,** as the receiver package was in 017.
